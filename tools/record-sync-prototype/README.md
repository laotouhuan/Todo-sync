# 独立记录文件同步原型

这是隔离的协议原型，用来回答：统一初始快照和同一组明确变更，能否在目录漏项、读取失败、乱序、重复、分批及进程退出后，最终恢复一致的完整结果。它不被应用导入，不修改正式 Schema，不迁移真实数据，不开发页面。

## 运行

在项目根目录使用 Node.js 18 或更高版本，无新增依赖：

```powershell
# 协议、客户端、HTTP替身和真实子进程退出测试
node --test tools/record-sync-prototype/tests/test-*.mjs

# 运行统一模拟场景；报告路径必须尚不存在
node tools/record-sync-prototype/run-simulation.mjs docs/record-sync-simulation-new.json

# 使用当前Windows连接，仅操作随机隔离测试目录
node tools/record-sync-prototype/run-live.mjs --execute docs/record-sync-webdav-new.json
```

代码按职责分为 `protocol.mjs`（纯重放）、`client.mjs`（原子本地状态及 outbox）、`transport.mjs`（内存／WebDAV）、`scenarios.mjs`（统一预置场景）。本地持久化在原型目录中的随机 `.scratch-prototype-*` 文件夹完成，不写应用缓存；测试结束只清理经过路径核对的本次文件夹。实际进程退出使用 `crash-worker.mjs`，不依赖父进程内存模拟重启。

## 固定数据依据

两客户端和冷启动客户端统一使用仓库中的 [fixture.json](fixture.json)，数据集 ID 为 `7dd247a0-d621-47e0-9a65-0b7cc65c2325`。每条记录携带该 ID 和统一快照的规范内容 SHA-256；相同 ID 配上不同快照也必须拒绝。原型不从当前个人 `todo_data.json` 生成初始快照，正式初始化另行设计。

数据依据是固定快照与不可变记录的集合。`todo_data.json` 仅是可重新生成的投影；修改、删除或丢弃该结果不能改变记录来源。目录不提供共享总索引，每次枚举只增加已知记录，一次漏项不代表删除。第一版不做记录清理、压缩、快照轮换或记录目录的生产维护。

记录只包含明确操作，例如新增指定任务、修改指定字段、设置某日评分、删除某个版本。一条保存意图可含多个操作，例如原子地新增周计划版本和采用记录；不接受把过时完整数据当成一次变更重新导入。

## 原型决策 P-001：因果关系和并发裁决

记录的 `parents` 指向客户端已应用的协议末端记录，`lamport` 为父记录最大值加一。依赖未齐的记录持久保留，暂不应用；依赖补齐后再校验并重放。协议层父记录与周计划采用记录的前驱属于两个不同关系，不能相互替代。

同一记录集按 `(lamport, actor_id, id)` 的固定 ASCII 次序重放。父记录总在子记录之前；真正并发时用固定身份裁决，不使用目录顺序、本地优先或当前设备时间。UUID 的排序只保证确定性，不表示某个用户的修改更合理。

派生数据的 `last_updated` 使用确定性重放中最后一条已应用记录的固定 `created_at`；没有记录时保留快照值。该字段只描述投影，不参与记录发现或裁决，不能因设备时钟倒退而丢弃因果后继。

这是一项待审核的原型协议决策，区别于现有普通 Todo 按 `updated_at` 选择整条、同时间保留本地的规则：原型使用字段 delta，因果后继优先，真正并发的同字段按稳定记录次序裁决；已有应用的合并实现保持不变。原型还将 Todo 和版本删除作为单调保留的操作，不提供恢复或七天清理。这些差异不能未经评审带入正式产品。评分与复盘仍独立保存，周计划仍保留完整历史与采用分歧，不自动选择并发版本。

后续 [ADR-0002](../../docs/adr/0002-first-release-rating-review-collaboration.md)已决定第一版评分与复盘保留原更新时间及平局规则，复盘多篇处理后置。此目录保留原实验及其报告，不回改历史证据；其中评分／复盘的因果赋值不能直接用于正式实现或视为兼容验收。

## 重试与恢复约束

UUID、actor、时间、父记录、逻辑时钟和操作正文均在一次提交中固定。提交先把完整记录和待上传状态写入本地原子状态文件，再发布或发送。重启读取同一份本地记录，不能把重试重建为新修改。

发送前读取同 ID 远端文件；相同规范内容可确认，不同内容立即报错，不能覆盖。上传后再读回核对；响应丢失时保持待确认状态，下次先读回。目录列出但读取暂时失败时保留诊断并重试；已读记录不会因后续列表漏项而消失。

该协议假设合法写入端不会为同一个 UUID 生成不同内容，并且只有固定规范内容会被重试。没有条件创建的服务上，两个违反此约束的写入端仍可能同时读到不存在再互相覆盖；原型不能宣称阻止这种行为。已观察到同 ID 不同内容时必须报错。

## 范围与后续

先完成统一模拟数据集的验证，再通过当前连接运行器在坚果云随机隔离目录实测。只使用预置测试数据，不读取正式待办文件。报告区分模拟故障与真实 HTTP 请求，并保留资源清理证据。

原型结果不能直接证明 Windows／Android 的正式集成、旧客户端兼容、协作授权、生产迁移或本地文件夹并发已经安全。这些仍需单独设计和验收。

2026-11-05 的[原型验证结论](../../docs/record-sync-prototype-results.md)记录模拟场景和坚果云实测，附带原始报告。真实实测结束后删除的是整个本次隔离测试的数据，不是协议中的记录回收；客户端同步从不删除记录。
