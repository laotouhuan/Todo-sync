## 三、逐项执行方案

### 1. 修复 Rust 旧协作配置迁移

**涉及文件：**[todo_store.rs](../windows/src-tauri/src/todo_store.rs)，以及同文件内的 Rust 测试模块。

**已核对的问题：**旧配置中的 `collaborations` 非空时，调用链为 `load_config()` → `get_collaborations_path()` → `load_config()`。旧字段尚未清除就再次加载，导致不断递归。迁移中的 `write_collaborations_file()` 同样会间接加载配置，不能只修第一处调用。现有代码还忽略目标文件写入结果，随后继续移除旧字段；解除递归后，这条失败路径会带来丢失迁移源的风险。

**执行步骤：**

1. 从本次已经读取的配置取得 `sync_path`。增加一个窄小的内部路径解析函数，接受已知配置/同步目录，按现有规则解析 `collaborations.json` 的位置；函数不得再次调用 `load_config()`。目录解析及创建仍是有副作用的操作，不将其描述为纯函数。此次不扩展到 WebDAV URL 或全部存储路径的整理。
2. 把迁移中需要的读、合并、写步骤放入可直接测试的内部入口，使用明确传入的路径。目标文件的读取、按 ID 合并及提交在同一把排他锁内完成，提交复用 `atomic_write()`；避免调用会重新加载配置或重复获取同一把锁的公开包装函数。
3. 保持迁移合并语义：相同 ID 保留目标文件中的已有项；只加入缺失 ID；仅为缺失字段补 `updated_at`、`deleted` 默认值，保留已有删除标记及文件扩展字段。已有目标文件读取/解析失败时停止迁移，保留文件，不把异常当成空清单覆盖。
4. 只有目标文件提交成功，才移除 `config.json` 中的旧 `collaborations` 字段并提交清理后的配置。迁移对配置文件的提交也使用原子写入；配置清理失败时保留可重试的旧源。重试通过 ID 去重，不重复导入或覆盖已有项。
5. 迁移失败时记录不含凭据的错误，保持现有 `load_config()` 返回类型和 Tauri 命令 API。可以返回已解析的内存配置，但不得从丢弃旧字段的 `AppConfig` 再回写磁盘。特别检查后续明文密码自动迁移：不能在协作迁移失败后间接清掉旧源；必要时延后本次密码回写。内存中的密码仍正常解密，成功落盘时保持现有 `ENC:` 规则。
6. 在生产迁移入口上增加少量回归测试，使用临时目录及最小的失败注入，不另造通用存储框架。

**验收用例：**

- 无旧字段、空旧列表及非空旧列表均能结束加载，不再递归；显式同步目录与默认数据目录均按原规则解析。
- 目标文件已有同 ID 项、删除标记及其他 ID 项时，迁移后全部按上述规则保留；重复加载不重复导入。
- 目标读取、写入/替换失败时保留原目标文件与旧配置；配置清理提交失败后，可再次加载并完成迁移。
- 迁移失败同时遇到明文密码时，后续密码处理不会清除旧源；原有明文/`ENC:` 密码的内存和磁盘语义保持。

**范围限制：**只处理迁移所需的路径与提交边界，不拆整个 `load_config()`、不重写全部配置持久化、不共用所有 WebDAV 传输。

### 2. 共用 Android 协作授权期限校验

**涉及文件：**[TodoRepository.kt](../android/app/src/main/java/com/todo/app/data/repository/TodoRepository.kt)；拟新增测试 `android/app/src/test/java/com/todo/app/data/repository/CollaborationExpiryTest.kt`。

**执行步骤：**

1. 把 `readCollaborationTodos()` 与 `writeCollaborationTodo()` 中重复的期限验证提取为同文件内部函数，输入为 `expireAt` 与服务端 `serverTime`，返回校验结果。为单元测试需要可使用 Kotlin `internal`，不新增公开服务或 Repository 类。
2. 两个入口均在下载得到服务端时间后调用它；失败继续按现有方式返回 `Result.failure`。下载、内容解析和上传的顺序不变，不扩大异常捕获范围，保留外层取消异常传播。
3. 保持 RFC 1123 解析、服务端时间来源和错误文字；不得改用设备时间代替缺失的服务端时间。

**验收用例：**永久授权无需有效 Date；有限授权在时间缺失/不可解析时返回“无法校验网络安全时间，授权已锁定”；早于或等于 `expireAt` 时通过，严格大于时返回 `EXPIRED`。测试直接调用同一个生产函数。

### 3. 共用 Android 统计类型筛选谓词

**涉及文件：**[StatsView.kt](../android/app/src/main/java/com/todo/app/ui/view/StatsView.kt)；拟新增测试 `android/app/src/test/java/com/todo/app/ui/view/StatsFilterTest.kt`。

**验收用例：**四种常规类型、空选择、全选择，以及同时带每日重复和周任务标记的兼容记录；混合标记记录在选择任一匹配类型时仍能通过。只测试谓词和真实筛选语义，不为本项引入 Compose UI 测试框架。

### 4. 固化发布版本检查的自动测试

**涉及文件：**[check-release-version.mjs](../scripts/check-release-version.mjs)、[release.yml](../.github/workflows/release.yml)；拟新增 `windows/tests/test-releaseVersion.mjs`，由现有 `npm run test` 自动发现。

**验收用例：**四处版本一致；四处分别不一致；字段缺失/为空；Cargo/Gradle 目标字段重复；其他区段出现同名字段不被误取；匹配/不匹配标签；分支手动运行；成功时输出正确的 `version=...`。不扩展成通用 TOML/Gradle 语法解析测试，也不实际触发发布。

**验收用例：**空列表；普通任务完成/未完成；周/月打卡有目标和无目标；超过目标时封顶；当前周期与周期外记录；纯日期和带时区时间戳；周统计无法解析的时间；混合任务下的总量与百分比。测试直接导入生产函数，预期值依据现有规则明确给出。页面核对日/周/月及类型筛选后的摘要和进度条。
